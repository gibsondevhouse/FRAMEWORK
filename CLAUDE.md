# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository layout

Two unrelated halves share this workspace:

- `reader/` — the only code: **FRAMEWORK**, a local-first, **federal-only** platform for staying up to date on codes and laws across federal frameworks (CFR, Federal Register, and U.S.C., with optional citation-grounded Claude research; Titles 29, 40, and 49 are the ones the integration tests expect, and any CFR title 1–50 can be built). FastAPI + SQLite FTS5 backend, strict TypeScript frontend. **Product direction (2026-11-19, synced with Linear `FRAMEWORK`):** federal codes and laws only; **state-law coverage and HSE-specific functions are out of scope**. **Immediate priority:** move the UI beyond its CFR-centric focus so CFR, Federal Register, and U.S.C. operate as peer federal frameworks without treating CFR as the default or primary framework. Existing DOL enforcement intelligence and HSE-oriented code remain supported in `reader/` as built foundation, but do not define product scope going forward.
- `docs/` — **Linear (`FRAMEWORK` / `P-DEV-2`) is the single source of truth for all active, upcoming, and future plans**; do not create new plan documents under `docs/plans/`. `docs/plans/` is retained strictly as a **historical archive** of earlier 10-series design plans (see [`docs/plans/README.md`](docs/plans/README.md)): **Implemented** in `reader/`: `12_repo_structure_stabilization/`, `13_frontend_architecture_and_hardening/` (decoupled zero-cycle TS architecture under `"checkJs": true`/`"strict": true`, centralized `src/api/` + `src/core/`, shared `doc_utils.ts`, perf/security/a11y hardening, Node JS unit tests + CI gates), `14_ui_visual_craft_and_typography/` (luminance-balanced `oklch` palette & tier tints, optical dark-mode font calibration & `66ch` legal prose measure, continuous `.reg-p` hierarchy thread guides, grounded card physics, control/chevron `mask-image` parity, horizontal table scroll cues, and unified `90–240ms` motion curves), `21_sliding_rail_sidebar/`, `22_editorial_download_refactor/`, `23_home_screen_refactor/`, `24_dark_newsroom_multi_jurisdiction_ui/` (dark-mode-only obsidian editorial palette, 9-tier semantic reference colors & `#btn-refs-ledger`, multi-framework `#/corpus/` routing & Tiered Corpus Switcher, Desk filters, Authority Stack strip, and Subject Workspaces housing nested Action Projects), `25_white_glove_ui_ux_refinement/` (Phase 1 visual craft fixes shipped; Phases 2–5 deferred in Linear behind the immediate federal multi-framework UI refocus), `31_reader_development/` (unified citation parser, deterministic anchors, hover peeks, Alt-click split pane, click-to-download, broadsheet Title start with the References & Authorities hub, Cited-by/IBR graph, clause Cite/Clip), `41_osha_news_interface/` (the `#/news` page and the inspection case file), `42_dol_api_expansion/` (shared DOL quota pacer + `429` breaker, bidirectional related inspections, contested/FTA/abatement & paragraph hotspots, unified GDC + accident FTS5 & core facets, explicit-submit `⌘K`/`#/news` DOL live search, Case File Workspace clipping, local-only Claude `search_enforcement` tool, and CLI `/v4/datasets` catalog + schema probe in `app/dol_catalog.py`), and `43_federal_register_and_ecfr_hardening/` (eCFR `429`/non-retryable `4xx`/edition-pinning/completeness meta + `/api/library/reload` + `.download` temp cleanup, multi-agency & installed-title Federal Register sync, cross-title `extract_all_citations` + `#btn-news-activity`, and on-demand sanitized/linkified `body_html_url` FR preamble reader at `#/news/fr/{document_number}`). **Archived / Superseded**: `51_hse_platform_roadmap/HSE_PLATFORM_ROADMAP.md` (HSE-specific suites and state-law coverage are out of scope) and `11_multi_title_foundation/` (historical record). `docs/notes/2026-11-16_pre-feature-orders.md` is the cleanup dev log (Orders 1–3 completed). `docs/bugs,quirks/` (the folder name contains a comma — quote it in shells) is the federal ingest quirks register: QUIRK-001/002 (duplicate appendix identifiers across parts in Titles 14 and 47) are **resolved** via part-qualified `{part}:{raw_id}` appendix ids in `ingest/tree.py` and `(kind, part, id)` staging in `ingest/parse.py`, Title 35 is reserved (eCFR returns 404, handled), loose-subpart nesting is QUIRK-004, QUIRK-005 (State Codes / Cal/OSHA) is out of scope, and QUIRK-006 covers U.S.C. statutory notes. The generated GovInfo/eCFR URL inventories (`docs/dev/`, `docs/title-29/`, `docs/title-29-api/`) are gitignored and absent from this clone; the app never reads them at runtime.
- `AGENTS.md` — the short cross-tool entry point (Codex, Gemini CLI, Cursor and other agents read it). It defers to this file for detail and lists only the contracts a change must keep; when this file changes in a way that affects those contracts, update it too.

Git repo (branch `main`). No linter and no `pyproject.toml` (deliberately: setuptools trips over the multiple top-level directories); Python deps are pinned in `reader/requirements.txt` (runtime) and `reader/requirements-dev.txt` (adds pytest + exact-pinned playwright/Pillow; browser tests need a one-time `python -m playwright install chromium`). The `origin/stage-*` branches and `stage-N-passed` tags are the merged stabilization history (PRs 1–7, Nov 16 2026), not active work. `README.md`, `reader/README.md` and `reader/API.md` describe the Regulatory Workstation for users and API clients (updated 2026-11-17); this file is the detailed description for working on the code.

`reader/data/` (SQLite DBs + tree JSON) and `.venv/` are gitignored, so a fresh clone has neither. The server starts empty on first run and shows a first-run profile picker (`GET /api/profiles`) so users can pick their regulatory domain or browse the Library instead of auto-downloading Title 29 on boot.

## Architecture (reader/)

**Multi-title federation.** Each installed title is its own SQLite DB (`data/title-{N}.sqlite3`) + tree (`data/tree-{N}.json`); `app/config.py` discovers installed titles by scanning `data/` (with legacy `title29.sqlite3`/`tree.json` fallbacks for 29). All API routes are title-scoped (`/api/{title}/…`) with unprefixed legacy aliases for Title 29; `/api/search?title=all` federates search across every installed title, merging by exact-match-then-bm25. Search results carry `title` (the title *number*) and `title_label` (the section heading) — keep both, tests and the frontend rely on this shape. Claude's tools take a `title` arg (number or `'all'`).

**Data pipeline — `app/build.py` + `app/ingest/`.** `build.py` is the orchestrator and CLI entrypoint (`python -m app.build`; `HEADERS`, `fetch_json`, `download_stream`, `log`, the SQLite schema and `build()` itself); the helpers live in `app/ingest/`: `tree.py` (`trim_tree`, `nest_loose_sections`, `disambiguate_leaf_ids`, `raw_leaf_id`, `normalize_scope`, `merge_scope`, `prune_tree`, `count_leaves`, `leaf_paths`, `renest` — which takes `log` as an injected parameter so it never imports build) and `parse.py` (`ecfr_path`, `front_matter_xml`, `stream_parse_xml`). `build.py` re-exports all of them, so `build.trim_tree`, `build.LEAF_TYPES`, … keep working (tests and `library/` use those names). Pulls from the eCFR Versioner API (not GovInfo), parameterized by `--title N`: `titles.json` → latest `up_to_date_as_of` edition → `structure/{edition}/title-{N}.json` + `full/{edition}/title-{N}.xml` (streamed to disk, parsed with iterparse to keep RAM flat). The **structure JSON drives ordering and hierarchy**; the full XML supplies text. eCFR's structure sometimes lists a subpart as an empty heading with its sections as siblings after it (29 CFR 1910 Subpart Z, Part 2520 Subparts D–F); `nest_loose_sections` moves them inside (plus any "Appendix … to Subpart X" after Subpart X), `disambiguate_leaf_ids` part-qualifies colliding/unqualified appendix IDs as `{part}:{raw_id}`, and `--renest` applies nesting to installed titles in place (atomic tree JSON + `sections.path` + `store.release_title`). Leaves are matched by `(kind, part, id)` where `DIV8` = section and `DIV9` = appendix; `DIV5`/`DIV6` (part/subpart) contribute only front matter (authority, source notes) into `front_matter` keyed `part/{N}` and `part/{N}/subpart/{N}`. Each `sections` row stores both raw `xml` (for HTML rendering) and flattened `text` (for FTS and for Claude), plus `ord` (global reading order used for prev/next) and `path` (JSON breadcrumb); `title_graph` stores the precomputed citation/IBR index (`graph.persist_title_index`). Writes go to a `.tmp` DB (closed deterministically via `closing()`) then atomically replace. Also writes `data/tree-{N}.json` (compact keys `t/id/l/d/c/r/range`) served verbatim to the sidebar. The eCFR API returns 406 unless `Accept-Encoding` is sent.

**Server — `app/main.py` + `app/routers/`.** `main.py` is only app init (GZip, `RevalidatedStaticFiles`, lifespan, `GET /`, `GET /healthz`) and router mounting; the endpoints live in domain routers: `routers/deps.py` (shared `valid_installed_title`, `require_key`, `NO_STORE`, `STREAM_HEADERS`, `ChatMessage`/`ChatRequest`), `routers/settings.py` (`/api/settings/env`), `routers/library.py` (`/api/library/…`, fixed paths declared before `/{title}`), `routers/news.py` (the old `news_api.py`, plus the enforcement case-file routes), `routers/reader.py` (`/api/titles`, `/api/titles/snapshot`, `/api/profiles`, `/api/search`, the `/api/{title}` reader routes including `GET /api/{title}/references` and `GET /api/{title}/citations/{id}` served from `app/citations/graph.py`, legacy un-prefixed aliases) and `routers/chat.py` (`/api/{title}/models|chat` + legacy `/api/models`, `/api/chat`). **Mounting order is a contract** (route_inventory snapshot + precedence tests): fixed-prefix routers before the `/api/{title}` routers, legacy aliases last. Routers import whole modules (`from .. import config, library, …`), never individual functions, so test patches on module attributes stay effective. Lifespan builds nothing on an empty install (`/api/titles` returns `[]`, and legacy un-prefixed Title 29 routes return `404` via `deps.valid_installed_title(29)` while 29 is absent). `store` uses thread-local read-only SQLite connections (`timeout=5.0`, `PRAGMA busy_timeout=5000`, `PRAGMA query_only=ON`; every one kept in `_registry` paired with a per-connection `RLock` acquired by `read_db()` and `release_title()`), plus title-scoped caches (`meta`, `known_ids`, `known_parts`, `_section_doc`, `section_html`, `unit_html`) that bypass caching during swaps (`_is_swapping`) and never cache transient `(sqlite3.Error, OSError)` failures. `store.begin_swap(n)` / `end_swap(n)` coordinate with `library.jobs.run_job` and `library.disk.remove` around installs/removals, and `store.release_title(n)` safely locks and closes every thread's connection to `n`, bumps its generation, and clears `n`'s caches (including the citation graph index via `graph.clear_caches(n)`). A CLI rebuild (`python -m app.build`) is seen after `POST /api/library/reload` (`library.reload_installed()`: `release_title` for every installed title, `store.clear_caches()`, the library structure cache cleared) or a server restart.

**Profiles / first run — `app/profiles.py`, `GET /api/profiles`, `views/welcome.js`.** `PROFILES` is pure data (`id`, `name`, `description`, `downloads` of `{title}` or `{title, part}` strings); `TITLE_NAMES` covers all 50 titles so the picker renders offline before any eCFR request. When `/api/titles` returns `[]`, `init` sets `state.noTitles = true`, disables search/chat (`setReaderEnabled(false)`), and `router.js` renders `renderWelcome()` for `/` and reader routes while keeping cross-title verticals (`/library`, `/news`, `/projects`, `/settings`, `/help`) reachable. Picking a profile queues downloads via `POST /api/library/download` (`installProfile`), `pollJobs` keeps the inline progress slot current via `refreshWelcome()`, and `refreshTitles()` wakes the reader and opens the first landed title's start page.

**Library — `app/library/`, `#/library…`.** A package: `client.py` (eCFR client + catalog caches `_catalog`/`_structures`), `suites.py` (`COMPLIANCE_SUITES`, `DESKS`, `_BLURBS`), `disk.py` (`installed`, `storage`, `prune_temp`, `remove`, `_remove_partial_files`), `views.py` (`title_view`, `part_view`, `changes`, `wire`), `jobs.py` (`Queue`, `run_job`, `queue_titles`, `update_all`, and the `queue = Queue()` instance) — deliberately **not** named `queue.py`/`storage.py`, which would shadow the re-exported `queue`/`storage()`. `library/__init__.py` re-exports the whole old surface, and submodules call every patchable function through the package (`lib.run_job`, `lib.queue`, `lib.ecfr_titles`, …) so test patches on `app.library` attributes stay effective. Download a whole title, a part or single sections/appendices (not paragraphs) from eCFR. A partial install stores its scope in `meta.scope` (`{"parts": [...], "sections": [{"t","id","part"}]}`; absent = whole title; `build.normalize_scope` drops sections inside selected parts). `build.build(scope=…)` prunes the structure (`prune_tree`, keeps ancestors) and fetches one XML per part (`?part=`), section (`?section=`) or appendix (`?part=&appendix=`, since appendix ids repeat across parts). Downloading more of a title rebuilds it with `merge_scope(old, new)` at the latest edition; the whole title replaces a partial copy; a same-scope same-edition request is a no-op ("Already installed"). Jobs run one at a time on a daemon thread (`library.queue`), reporting `phase/done/total` via `build(progress=…)`. Endpoints: `GET /api/library` (all 50 titles + install state + jobs + `desks`; each title row also carries `summary`, `desk`, `featured` from `app/title_blurbs.json` and `amended` = eCFR's `latest_amended_on`; a title with no entry in the JSON gets an empty summary and the "More titles" desk), `GET /api/library/{t}` (parts by chapter), `GET /api/library/{t}/part/{p}` (sections by subpart), `POST /api/library/download` `{title, part?, section?, kind}`, `POST /api/library/{t}/update`, `DELETE /api/library/{t}` (refused for the last installed title or one with a job), `GET /api/library/jobs`. eCFR's title list is cached 30 min, structures per (title, edition). Frontend: `loadLibrary`/`renderLibrary` (three levels like the sidebar, filter box, row actions that swap with the status column on hover, Remove is two clicks). The top level (`libFrontHtml`) is a newsroom front page, built from `docs/plans/20_app_shell_and_workspace/22_editorial_download_refactor/`: masthead (edition, active titles, amended this week) → four metric tiles (`libMetrics`: eCFR checked-at, installed count/sections/disk, amended in the 7 days before the newest edition, outdated editions with **Update all**) → the broadsheet lead, the featured compliance suite (`suiteHero`, 65%: its titles with agencies, top parts from `HOME_CONTENT`, per-title dateline and status, one batch button) beside **The Regulatory Wire** (`libWire`, 35%: the five most recently amended titles; what changed fills in from `GET /api/library/wire`, cached client-side 30 min) → the other suites (`suiteCard`) → filter + order control (desk / number / recently amended, `localStorage` `libSort`) → every title as a brief (`libStory`) under its topic desk, desk headers counting titles ("2 of 6 titles" while filtering). A brief: kicker ("Title 29 · OSHA WHD EBSA"), status pill top right, headline (the whole card links to `#/library/{t}`), summary, dateline (amended · sections · size); actions (`titleActions`) slide in over the dateline on hover/focus, painted in the card's colour (`--story-bg`). The filter matches number, name, summary, desk and agency acronyms. Widths follow the page via container queries (`.lib-front` is `container: lib`): 3 brief columns ≥1000px, metrics 2×2 and the broadsheet stacked ≤760px, 1 column ≤560px. Status is a 6px dot + word everywhere (`statPill(state, text)`; states synced / stale / busy / partial / uninstalled; `is-bare` drops the outline in dense rows); `titleStatus(t)` decides a title's. The summaries are scope-only editorial copy (≤140 chars, enforced by `tests/test_library_front_page.py`); `title_blurbs.json` also holds each title's main `agencies` (acronyms) and the measured `size_mb`/`sections` estimates (from eCFR's structure JSON, 2026-11-12 edition). eCFR's `search/v1/counts/titles` is not a section count (it disagrees with installed counts), so it isn't used. Suites are `library.COMPLIANCE_SUITES` (ehs 29/40/49 featured, trade 12/15/17, govcon 41/48); a new one is one dict entry. Batch endpoints: `POST /api/library/batch-download` `{suite}|{titles}` (`library.queue_titles`: skips reserved and current titles, updates stale whole ones, completes partial ones), `POST /api/library/update-all` (`library.update_all`, keeps each title's scope), `POST /api/library/jobs/{id}/cancel`, `POST /api/library/jobs/clear`. Cancelling a running job sets `cancelling`; the job's progress callback raises `JobCancelled` at its next report (never once it reports `Installing`, when files are being swapped) and `_remove_partial_files` deletes its `.tmp` files. While a whole title's XML streams, `build` reports bytes against Content-Length or, without one, decoded bytes against the structure's `size`, so the dock can show real progress, speed and ETA. **Transfer dock** (`#transfer-dock` in `index.html`, "Transfer dock" in `app.js`): a floating card at the bottom right of the reading panel (moves left of the chat when it's open; hidden under 900px while the chat covers the page), mounted outside `#view` so routing never touches it; `setJobs` → `updateDock()`. It shows the running job, its pipeline step (`DOCK_STEPS`, six ticks), a 3px progress bar (indeterminate when unmeasured), MB of MB · speed (EMA over polls) · time left, and what's queued, with Cancel and Clear queue; it minimizes to a pill (`localStorage` `dockMinimized`). It rebuilds its markup only when its shape changes (job, step, queue) and patches numbers in place otherwise, so the bar animates and focus stays put; screen readers get one polite line per step (`#transfer-dock-live`). `pollJobs` (runs while jobs are active, wherever the reader is; on completion toasts — done, error or cancelled — `refreshTitles()` refills the title switcher and reloads the current title if it changed; the library re-renders only when the set of active jobs changes), entered from Home's **Manage library** / **Add or update titles** links or the Library rail button. `/api/titles` carries `partial`. **Rendering — `app/render/`.** A package (`text.py` plain-text flattening, `hierarchy.py` `LevelTracker`/`compute_levels`, `linkifier.py` citation regexes + `make_linkifier`, `units.py` `SectionDoc`/`split_units`, `html.py` `Renderer`/`image_urls`/`render_leaf_html`/`render_fragment_html`); `render/__init__.py` re-exports everything, so `from .render import …` is unchanged (`news.py` imports `_CROSS_TITLE`/`_XREF`/`_NUM_IN_LIST` from it). `units.py` defers its `Renderer` import inside methods because `html.py` imports `units` at the top. HTML is rendered from stored XML on request (cached), not at build time. `LevelTracker` infers indentation depth from paragraph markers `(a)→(1)→(i)→(A)`. A lone `(i)`/`(v)`/`(x)` is both a letter (level 1) and a roman numeral (level 3); it is resolved from the next paragraph's marker (`(ii)` → roman, `(j)` or `(1)` → letter) and from what came before (last clause letter, last roman). `compute_levels(root)` runs the tracker once over the whole section, keyed by `id(element)`, so rendering any slice indents exactly as the full text does; `Renderer` only looks levels up. `make_linkifier` turns `§`/`§§` citations (lists, ranges, paragraph suffixes) into links, but only for IDs present in `known_ids()`. **Units — `SectionDoc` / `split_units` in `render/units.py`.** Every section is cut into reading units: each top-level lettered clause `(a)`, `(b)`, … (text before `(a)` joins it), and each appendix embedded in the section as an `<EXTRACT>` headed "Appendix X to §…" (58 Title 29 sections do this, e.g. § 1910.1200, § 1910.1027, § 1910.134). An embedded appendix over `APPENDIX_SPLIT_MIN_CHARS` splits again at its own HD1 headings (A.0, A.1 …; HD2 as fallback; Figure/Table captions skipped); a long standalone text with no clauses splits the same way. A section is `mode: "units"` (read a unit at a time) when it has an embedded appendix or more than `UNIT_MODE_MIN_CHARS` of text; otherwise `"page"`. `full_html()` wraps each unit in `<section class="reg-unit" id="u-{key}">` and renders embedded appendices plainly (no extract callout). Unit keys: clause letter (`c`), `appendix-a`, `appendix-a-a-1` (chapter A.1); a group key opens its first chapter. `store._section_doc` caches the parsed doc; `section_html` / `unit_html` cache renders. `GET /api/{title}/section/{id}` returns `mode`, `outline` (every unit: key, label, title, kind, group, group_label, group_title, chars) and, with `?unit=KEY` (`?unit=` = first) on a units-mode section, only that unit's `html` plus `unit`, `unit_prev`, `unit_next`; without `unit` it returns the whole section as before.

**IDs.** `store.normalize_id` accepts `§ 541.100`, `29 CFR 541.100`, `541.100(a)(1)` → `541.100`. All endpoints and Claude tools go through it.

**Search — `store.search`.** Exact section-number hit is prepended, then FTS5 (`porter unicode61`) ranked by `bm25` weighted toward label/title. `fts_query` quotes every token (so user input can't inject FTS syntax) and adds a prefix `*` to a final bare token of ≥5 chars. Surfaces follow the obsidian ink ramp `--bg` (`#070708`) → `--panel` (`#0B0B0D`) → `--card` (`#111114`) → `--pop` (`#151519`), inset chrome (`12px` radius, hairline `--line` border), text opacity ramp (`--fg` / `--fg-2` / `--fg-3` / `--fg-4`), surgical editorial stamps (`--editorial-crimson: #E11D48`, `--editorial-gold: #EAB308`), and **9-tier semantic reference colors** (`--ref-local`, `--ref-cfr`, `--ref-cross`, `--ref-uninstalled`, `--ref-usc`, `--ref-fr`, `--ref-ibr`, `--ref-state`, `--ref-county`) driving inline `.xref*` links, `.citation-chip[data-ref-tier]`, `.has-tier-bar` 3px left bars, `#cite-pop[data-ref-tier]` 2px colored top borders, and `.split-head[data-ref-tier]`. `--fig-mat` uses warm dark-room slate (`#D4D4D8`) for Federal Register diagrams. Status (`statPill`) remains strictly reserved for sync/download state. Layout breakpoints inside panes use `@container` queries (`.main` → `main`, `.split-pane` → `split`, `.ts-front` → `title-start`, `.hm` → `hm`, `.lib-front` → `lib`, `.news-front` → `news`, `.settings-front` → `settings`, `.help-front` → `help`).

**Navigation — two-layer primary sidebar + contextual secondary framework drawer (`nav.ts`, `03_layout.css`).** The layout is four fixed grid tracks, `var(--rail-w) var(--drawer-col) minmax(0,1fr) var(--chat-col)`, animating smoothly between states. The **primary sidebar** (`#activity-rail`, `216px` expanded on main pages, automatically compacting to a `52px` icon rail via `html.in-framework` when inside a legal framework or `html.rail-compact` via `⌘B` on main pages) navigates **main pages directly** via links: **Home** (`#/`), **Workspaces** (`#/projects`, with live count pill), **Newsroom** (`#/news`, with cached filings pill), **Library** (`#/library`, with `#ar-library-badge` / `#ar-library-pill` for active downloads or stale updates), and **Settings** (`#/settings`) + **API & Sources** (`#/help`) pinned at the bottom, plus a dynamic **Frameworks** quick-jump list (`#ar-frameworks`) grouped by `Statutes (U.S.C.)`, `Regulations (CFR)`, and `Rulemaking (FR)` with semantic OKLCH tier bars and stale indicators (no State/County tiers). The topbar framework switcher (`#title-select` in `title_switcher.ts`, synced on `route:changed`) adapts to the active context: `Federal · All Frameworks` on main pages, `FR · Federal Register` on Newsroom/FR routes, `{code} · {name}` on U.S.C./corpus routes, and `{N} CFR · {name}` (with `eCFR {date}` in `#edition`) inside a CFR title. Under 900px the primary sidebar becomes a bottom navigation bar (`--bar-h`). The **secondary framework drawer** (`#sidebar`, `288px` resizable) is **strictly contextual**: `isFrameworkRoute(path)` opens it ONLY while inside a federal framework — specifically a Framework **Start page** (`#/title/{n}/`, `#/corpus/{tier}/{jur}/{code}/`), **Table of Contents / Full Part** (`#/title/{n}/part/{p}`), or **Section Reader** (`#/title/{n}/section/{id}`) — and retracts it (`html.drawer-retracted`, `--drawer-col: 0px`) on all main pages (`Home`, `Workspaces`, `Newsroom`, `Library`, `Settings`, `Help`, `Search`). Its 42px header carries a tier-colored top border + `#drawer-pip`, framework code, metadata, a `Start` quick-jump pill when deep inside a title, pin/overlay mode toggle, and close button (`⌘B`). It hosts `#panel-reader` (the 3-tier CFR drill-down contents tree) and `#panel-corpus` (the contextual outline for FR and U.S.C. framework views). State persists in `localStorage` `railState` `{panel, collapsed, mode, width, railCompact}` (mirrored pre-paint by the blocking `<head>` script in `index.html`). **`#/settings` page** (`renderSettingsPage`): cards for Appearance, Claude model (mirrors `#model-select`), News status, storage (`GET /api/library/storage`, `POST /api/library/storage/prune`), and the keyboard cheatsheet. Keys: `⌘B`/`Ctrl+B` toggles the secondary framework drawer inside a framework (or compacts/expands the primary sidebar on main pages); **G then H/P/N/L/S/T/C** navigates main pages and framework start/contents (`G O` aliases `G H`); `Alt/⌥+1…7` follows `NAV_TARGETS`; `⌘D` pins; `Esc` closes a floating drawer; `>` in the search box lists commands (`commandList`). A hidden drawer is `inert`.

**Projects (`views/projects.js`, labeled "Workspaces" in the UI).** Workspaces of pinned sections, per browser in `localStorage` `framework_projects_v1`: `{id, name, description, tags[], created_at, updated_at, sections[{title, id, label, heading, part, pinned_at, note}]}`. A clause **Clip** (`clipToWorkspace(sec, {para, quote, cite, projectId})`) pins the section if needed (into the first workspace, creating "Research clips" when there is none) and appends a `[cite] "quote"` line to that section's `note` — clips are not a separate field. Pin the open section with the **Pin** button in the section's actions row or ⌘D: a popover lists workspaces as checkable rows and creates a new one from its input. `#/projects` lists workspaces as briefs (kicker with the workspace's colour dot from `PROJECT_HUES` tokens, name, description, tags, "N sections · Titles …"); `#/projects/{id}` edits in place (name as the headline input, description, tags, a note per pinned section; saved 300ms after typing with `saveProjects(…, {quiet: true})` so the page isn't re-rendered under the cursor), with Export (JSON) and two-click Delete/Remove. Sections of titles that aren't installed say so and link to the library. The drawer's Workspaces panel lists workspaces (current one lit), creates them inline, and exports/imports all of them via "Import file" (`{format: 'framework-projects', version: 1, projects}`; an import keeps the newer copy of a workspace by `updated_at`).

**Sidebar (`app.js`, "Sidebar: drill-down contents"; the drawer's Contents panel).** Three-tier drill-down & drill-up model: Tier 1 lists the 15 agencies (Subtitle A plus each Subtitle B chapter) as compact rows: code, short name from `AGENCY_META` (keyed by title number first, because chapter numbers repeat across titles; unlisted chapters fall back to `Ch. N` plus their own heading), and "Parts X–Y · N parts"; the "All N parts" tab instead lists every part under small agency labels. Tier 2 is one agency's parts (subchapters as labels); Tier 3 is one part's sections, grouped under foldable subpart headings (the user asked for these): each heading is a `.side-group-toggle` button with a caret, the body folds with a grid-rows transition, Alt-click folds/opens all, folded subparts persist in `localStorage` `sideFolded` as `"{title}|{part}|{subpart}"`, and the subpart holding the page on screen opens itself (in `partViewHtml` and `refreshCurrent`). Subject-group labels inside subparts stay plain. Keep it restrained: the user rejected badges, chips, per-row tags and duplicate back buttons as clutter. The sticky header is one clickable breadcrumb plus one title; the breadcrumb follows `rootViewMode` (`Agencies › OSHA › Part 1910` or `All parts › Part 1910`), and the mode switch ("By agency / All N parts" segmented pill) stays visible at every tier, lit from `rootViewMode` (the user asked to keep it; clicking an option returns to that top-level list) and hides only while the filter has text. `indexTree` stamps every `tree.json` node with a preorder key `k`, a match string `hay` (agency nodes also get their `AGENCY_META` code and name, so "osha" or "erisa" filters to the agency), a leaf count `n`, and `partCount`; `treeIdx` holds parent links, id→key maps, and agency maps. Other views call `selectTreeNode('s-<id>' | 'p-<id>')`, which switches the list to that part and resolves `agencyOf(k)`; Home, Search and not-found call `clearTreeSelection()`. Selection has two states, set both at render time (`itemHtml`, `agencyRowHtml`, `partViewHtml`) and in `refreshCurrent()`, so change them together: `.current` + `aria-current="page"` only on the page on screen (filled pill), `.ancestor-current` on the part/agency containing it (accent text, no fill). Agencies are never `.current`. The filter box (`computeFilter`) matches word prefixes across a node and its ancestors, returns agencies, parts and sections grouped under agency labels (`groupedHtml`), and is separate from the server's FTS search. Per-viewer state in `localStorage`: `visited`, `rootViewMode` ('agencies' | 'all-parts'); the drawer's width and visibility are the navigation's (below). The system prompt asks Claude to cite as `§ 541.100(a)(1)` because the UI linkifies that form.
