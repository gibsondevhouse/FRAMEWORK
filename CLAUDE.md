# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository layout

Two unrelated halves share this workspace:

- `reader/` — the only code: a local web reader + Claude research assistant for multiple CFR titles (29 Labor, 40 EPA, 49 DOT are the ones the integration tests expect; any title 1–50 can be built). FastAPI + SQLite FTS5 backend, vanilla JS frontend.
- `docs/` — `docs/plans/roadmap/HSE_PLATFORM_ROADMAP.md` is a strategy/blueprint document (MCP server, hybrid RAG, policy linter, enterprise bots, …); none of it is implemented, so don't treat it as a description of the code. The generated GovInfo/eCFR URL inventories (`docs/dev/`, `docs/title-29/`, `docs/title-29-api/`) are gitignored and absent from this clone; the reader never reads them at runtime.

Git repo (branch `main`). No linter, no `requirements.txt`, no `pyproject.toml`. `README.md`, `reader/README.md` and `reader/API.md` describe the multi-title reader for users and API clients (updated Nov 2026); this file is the detailed description for working on the code. `docs/plans/roadmap/phase-1_multi-title/` holds the agent prompt and completion report from the multi-title work — historical records (Windows paths, Nov 2026 counts), not current instructions.

`reader/data/` (SQLite DBs + tree JSON) and `.venv/` are gitignored, so a fresh clone has neither. The server's lifespan auto-builds Title 29 on first start if no title is installed (one network download from eCFR, ~28 MB of XML).

## Commands

The project was authored on Windows; this clone is on macOS. Python **3.10+** is required (the code uses `X | None` annotations; the macOS system `python3` is 3.9 and will fail at import — on this machine the venv is built from Homebrew `python3.12`). The venv lives at the repo root (`.venv`); commands run from `reader/` because the backend is the package `app`.

macOS / Linux:

```bash
python3.12 -m venv .venv && .venv/bin/pip install fastapi "uvicorn[standard]" httpx anthropic python-dotenv pytest   # one-time, from repo root
cd reader
../.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload   # run server
../.venv/bin/python -m app.build              # build default title (29) only if missing
../.venv/bin/python -m app.build --title 40   # build/install another CFR title
../.venv/bin/python -m app.build --force      # re-download latest eCFR edition and rebuild
../.venv/bin/python -m app.build --title 29 --renest   # fix subpart nesting of an installed title, no download
../.venv/bin/python -m pytest tests -q                       # all tests
../.venv/bin/python -m pytest tests/test_units.py -q         # one file
../.venv/bin/python -m pytest tests -q -k test_fixture_parse # one test
```

Windows / PowerShell: same commands with `..\.venv\Scripts\python` in place of `../.venv/bin/python`.

Tests are `unittest.TestCase` classes (pytest collects them; `python -m unittest discover tests` works too) and all run on a fresh clone with no network and no titles downloaded. `tests/fake_titles.py` builds three tiny fake titles (29, 40, 49: 29 CFR 1910.120/1910.134/1910.135/1910.1200, 40 CFR 261.2/261.3, 49 CFR 172.101/172.102) into a temp `DATA_DIR` by patching `config.DATA_DIR`, `build.fetch_json`, `build.download_stream` and `build.log`; `test_api_endpoints.py` and `test_federated_store.py` install them in `setUpClass` via `FakeTitles().install()` / `.remove()`. The real numbers are used because `DEFAULT_TITLE` is 29 and the sections mirror the cross-title citation trio (1910.120 cites 40 CFR 261.3 and 49 CFR 172.101); 1910.1200 is long enough (clauses a–j, an `(i)` after `(h)`, an embedded appendix split into chapters A.1–A.4 with a figure) to exercise units mode. `test_library.py` does the same with a fake "Title 99" for partial-scope builds. Follow either pattern for new tests that need a database; never depend on what is installed in `reader/data/`.

Titles, parts and sections can also be downloaded from inside the app (Overview → Installed titles → Download). A CLI rebuild needs a server restart to be seen (see `store` caches below).

Config is `reader/.env`, loaded by `app/config.py` (copy `reader/.env.example`, which is tracked): `ANTHROPIC_API_KEY` (optional — reader and search work without it) and `ANTHROPIC_MODEL` (preferred default; if the key can't see that model, `chat.pick_default_model` falls back to the first sonnet/opus/haiku from the live `/v1/models` list).

## Architecture (reader/)

**Multi-title federation.** Each installed title is its own SQLite DB (`data/title-{N}.sqlite3`) + tree (`data/tree-{N}.json`); `app/config.py` discovers installed titles by scanning `data/` (with legacy `title29.sqlite3`/`tree.json` fallbacks for 29). All API routes are title-scoped (`/api/{title}/…`) with unprefixed legacy aliases for Title 29; `/api/search?title=all` federates search across every installed title, merging by exact-match-then-bm25. Search results carry `title` (the title *number*) and `title_label` (the section heading) — keep both, tests and the frontend rely on this shape. Claude's tools take a `title` arg (number or `'all'`).

**Data pipeline — `app/build.py`.** Pulls from the eCFR Versioner API (not GovInfo), parameterized by `--title N`: `titles.json` → latest `up_to_date_as_of` edition → `structure/{edition}/title-{N}.json` + `full/{edition}/title-{N}.xml` (streamed to disk, parsed with iterparse to keep RAM flat). The **structure JSON drives ordering and hierarchy**; the full XML supplies text. eCFR's structure sometimes lists a subpart as an empty heading with its sections as siblings after it (29 CFR 1910 Subpart Z, Part 2520 Subparts D–F); `nest_loose_sections` moves them inside (plus any "Appendix … to Subpart X" after Subpart X), and `--renest` applies that to installed titles in place (tree JSON + `sections.path`). Leaves are matched by `(kind, N)` where `DIV8` = section and `DIV9` = appendix; `DIV5`/`DIV6` (part/subpart) contribute only front matter (authority, source notes) into `front_matter` keyed `part/{N}` and `part/{N}/subpart/{N}`. Each `sections` row stores both raw `xml` (for HTML rendering) and flattened `text` (for FTS and for Claude), plus `ord` (global reading order used for prev/next) and `path` (JSON breadcrumb). Writes go to a `.tmp` DB then atomically replace. Also writes `data/tree.json` (compact keys `t/id/l/d/c/r/range`) served verbatim to the sidebar. The eCFR API returns 406 unless `Accept-Encoding` is sent.

**Server — `app/main.py`.** Lifespan auto-runs a forced build if no title is installed. `store` uses thread-local SQLite connections (every one also kept in a registry) and `lru_cache`s (`known_ids`, `section_html`, `meta`, …). `store.release_title(n)` closes every thread's connection to a title, bumps its generation (each thread reopens on its next query) and clears the caches; the library calls it before replacing or deleting a title's files, because Windows refuses while any handle is open. A CLI rebuild (`python -m app.build`) still needs a **server restart** to be seen.

**Library — `app/library.py`, `#/library…`.** Download a whole title, a part or single sections/appendices (not paragraphs) from eCFR. A partial install stores its scope in `meta.scope` (`{"parts": [...], "sections": [{"t","id","part"}]}`; absent = whole title; `build.normalize_scope` drops sections inside selected parts). `build.build(scope=…)` prunes the structure (`prune_tree`, keeps ancestors) and fetches one XML per part (`?part=`), section (`?section=`) or appendix (`?part=&appendix=`, since appendix ids repeat across parts). Downloading more of a title rebuilds it with `merge_scope(old, new)` at the latest edition; the whole title replaces a partial copy; a same-scope same-edition request is a no-op ("Already installed"). Jobs run one at a time on a daemon thread (`library.queue`), reporting `phase/done/total` via `build(progress=…)`. Endpoints: `GET /api/library` (all 50 titles + install state + jobs), `GET /api/library/{t}` (parts by chapter), `GET /api/library/{t}/part/{p}` (sections by subpart), `POST /api/library/download` `{title, part?, section?, kind}`, `POST /api/library/{t}/update`, `DELETE /api/library/{t}` (refused for the last installed title or one with a job), `GET /api/library/jobs`. eCFR's title list is cached 30 min, structures per (title, edition). Frontend: `loadLibrary`/`renderLibrary` (three levels like the sidebar, filter box, row actions that swap with the status column on hover, Remove is two clicks), `pollJobs` (runs while jobs are active, wherever the reader is; on completion toasts, `refreshTitles()` refills the title switcher and reloads the current title if it changed), entered from the **Download** button in the Overview's "Installed titles" header. `/api/titles` carries `partial`. If Title 29 is not installed, the frontend starts on the first installed title.

**Rendering — `app/render.py`.** HTML is rendered from stored XML on request (cached), not at build time. `LevelTracker` infers indentation depth from paragraph markers `(a)→(1)→(i)→(A)`. A lone `(i)`/`(v)`/`(x)` is both a letter (level 1) and a roman numeral (level 3); it is resolved from the next paragraph's marker (`(ii)` → roman, `(j)` or `(1)` → letter) and from what came before (last clause letter, last roman). `compute_levels(root)` runs the tracker once over the whole section, keyed by `id(element)`, so rendering any slice indents exactly as the full text does; `Renderer` only looks levels up. `make_linkifier` turns `§`/`§§` citations (lists, ranges, paragraph suffixes) into links, but only for IDs present in `known_ids()`. HTML output is escaped/whitelisted (e.g. `SAFE_CELL_CLASSES`). Figures: eCFR's `/graphics/erDDmmmYY.NNN.gif` paths are dead; `image_urls` maps them to `img.federalregister.gov/{ID}/{ID}_large.png` (what eCFR itself uses), wrapped in a `.reg-figure` link to `_original_size.png`. ~45 legacy names (`53-49a.eps.gif`) have no known URL; the reader swaps a failed figure for a "view on eCFR" link.

**Units — `SectionDoc` / `split_units` in `render.py`.** Every section is cut into reading units: each top-level lettered clause `(a)`, `(b)`, … (text before `(a)` joins it), and each appendix embedded in the section as an `<EXTRACT>` headed "Appendix X to §…" (58 Title 29 sections do this, e.g. § 1910.1200, § 1910.1027, § 1910.134). An embedded appendix over `APPENDIX_SPLIT_MIN_CHARS` splits again at its own HD1 headings (A.0, A.1 …; HD2 as fallback; Figure/Table captions skipped); a long standalone text with no clauses splits the same way. A section is `mode: "units"` (read a unit at a time) when it has an embedded appendix or more than `UNIT_MODE_MIN_CHARS` of text; otherwise `"page"`. `full_html()` wraps each unit in `<section class="reg-unit" id="u-{key}">` and renders embedded appendices plainly (no extract callout). Unit keys: clause letter (`c`), `appendix-a`, `appendix-a-a-1` (chapter A.1); a group key opens its first chapter. `store._section_doc` caches the parsed doc; `section_html` / `unit_html` cache renders. `GET /api/{title}/section/{id}` returns `mode`, `outline` (every unit: key, label, title, kind, group, group_label, group_title, chars) and, with `?unit=KEY` (`?unit=` = first) on a units-mode section, only that unit's `html` plus `unit`, `unit_prev`, `unit_next`; without `unit` it returns the whole section as before.

**IDs.** `store.normalize_id` accepts `§ 541.100`, `29 CFR 541.100`, `541.100(a)(1)` → `541.100`. All endpoints and Claude tools go through it.

**Search — `store.search`.** Exact section-number hit is prepended, then FTS5 (`porter unicode61`) ranked by `bm25` weighted toward label/title. `fts_query` quotes every token (so user input can't inject FTS syntax) and adds a prefix `*` to a final bare token of ≥5 chars. Snippet highlights use `\x02`/`\x03` sentinels that the frontend/chat replace.

**Claude — `app/chat.py`.** A hand-written tool-use loop (max `MAX_TOOL_ROUNDS = 10`) over the Messages streaming API with three local tools: `search_regulations`, `read_section` (chunked by `offset`, 40k chars), `list_part`. The currently open section is injected as a second system block with `cache_control: ephemeral`. The model is chosen client-side and sent with every `/api/chat` request. Errors are mapped to user-facing text by `friendly_error`.

**Streaming contract.** `/api/chat` returns SSE lines `data: {json}` with `type` ∈ `text | tool | tool_result | done | error`. `static/app.js` parses these manually via `res.body.getReader()` — keep both sides in sync when changing event shapes.

**Frontend — `static/`.** Single IIFE in `app.js`, hash router (`#/`, `#/section/{id}`, `#/section/{id}/{unit}`, `#/section/{id}/full`, `#/part/{id}`, `#/part/{id}/full?from={section}`, `#/search?q=&scope=`, all optionally prefixed `#/title/{n}/…`; a topbar title menu (`#title-select` button + `#title-pop`, filled by `fillTitleSelect`: "Download titles…" → `#/library` first, then installed titles with number column, "Partial" note and a check on the current one; full keyboard support; not a native select) switches titles via `switchTitle`, which resets `treeIdx` field-by-field — it's a `const`). The app is branded **FRAMEWORK** (topbar wordmark, the E in `--accent`; under 600px only the E shows), and the wordmark is the home button: `#/` is the cross-title **Overview** (`renderOverview`: across the top, three 2:3 portrait cards for the three most visited titles (large title number, name, visits, and its four most read sections; unopened titles fill empty slots; the cards drop the fixed shape under 700px), then metric tiles, most visited titles/parts/sections, recently read, installed-titles table), while `#/title/{n}/` is that title's start page (`renderHome`, curated cards). Overview numbers come from localStorage `usage` (`{v, since, s: {"29|1910.1200": {n,t,l,h,p}}, p: {"29|1910": {n,t,h}}}`, written by `recordSectionVisit`, once per section load, so stepping through clauses is one visit, and `recordPartVisit`; title totals are the sum of their parts), plus the older per-title `visited` sets for "sections read". It is per-browser by design. Every route bumps `routeSeq`; loaders capture it and bail after each `await` if it changed, so a slow page can't paint over the one the reader moved to. Static files are served with `Cache-Control: no-cache` (`RevalidatedStaticFiles` in `main.py`) so updates aren't hidden by stale cached JS/CSS. Home page content and chat starter prompts are per-title maps (`HOME_CONTENT`, `HOME_PROMPTS`); `visited` is stored per title (`visited` for 29, `visited-{n}` otherwise). Markdown from Claude is rendered with vendored `marked` + `DOMPurify` (offline, `static/vendor/`). Theme and font size persist in `localStorage`. Previous/next navigation is the main panel's header: `#view-head` (a sibling of `#view` inside `.main`, filled by `setViewHead(docStepHtml(…))`) is pinned to the top of the reading panel as frosted glass whose tint and blur fade out downward (`.view-head::before`: gradient background + `backdrop-filter` + `mask-image`). Layout is `‹ part | ‹ section … section › | part ›`; a part page offers its own first section as "next section"; buttons show just the number and a hover/focus popup (`.tip`) gives the name. Home, search and not-found hide it with `setViewHead('')`. The main panel has no breadcrumb (the user found it redundant): the line above the title (`.doc-kicker`, "29 CFR Part 1910") places the page, and on section pages its "Part N" links to the part. There are no prev/next cards at the bottom of a section, and none in the sidebar — the user asked for this placement.

**Three ways to read (the user's model — keep it).** A long section is read **clause by clause** (one unit at a time, the default at `#/section/{id}`, which opens the first unit; `?p=(f)(1)` opens clause (f)); **"See full section"** (`/full`) shows all of it; **"See full part"** shows the whole part. Short sections are one page. In unit view the pinned header is `‹ section | ‹ unit … unit › | section ›` (`unitStepHtml`), so stepping walks the whole section, clauses then appendix chapters, and spills into the neighbouring sections at the ends; elsewhere it is `‹ part | ‹ section … section › | part ›`. Chapters after the first in an appendix get a `.unit-context` line ("Appendix A · Health Hazard Criteria"). The user rejected collapsible sections, an inline TOC box and per-paragraph ticks — don't bring them back.

**The rail (`railHtml`, `.rail`).** Modelled on the stacked message bars in Claude's chat: a tight column of equal-length bars inside `#view-head` (so it stays pinned), in the reading panel's left gutter and vertically centred in the panel, one per unit, with a gap between groups (the rule, then each appendix). At rest bars are ~20% opacity; the whole rail brightens under the pointer; the current unit is lit in `--accent`. Hover is JS, not `:hover` (`bindRail`): the bar nearest the pointer is picked with hysteresis so small drifts don't hop to a neighbour, and one shared label (`.rail-pop`, "A.1 Appendix A · Acute Toxicity") appears in place beside it, glides between bars, stays open while the pointer is on it, and is itself a link. Hover never scrolls; the user asked for exactly this. In unit view bars are links to `#/section/{id}/{unit}`; on a full page they scroll to `#u-{key}` and `watchRail` lights the unit under the header (scroll + image-load listeners, torn down via `railObserver.disconnect()` in `setViewHead`). The rail must not scroll (`overflow` would clip the tooltips); rows shrink via `--rows` instead. Shown for any section with 2+ units; hidden under 900px.

**Full-part view (`loadPartFull`, `GET /api/{title}/part/{id}/full`).** Every section of a part rendered in reading order, plain and uncollapsed, under its own `<article id="sec-{id}">` anchor, each with its own § number header that links back to the single-section view. No rail here (one bar per section would be hundreds). "See full part" on a section page links to `#/part/{id}/full?from={sectionId}`; on arrival, the target section is scrolled into view with `scrollIntoView` re-anchored every frame for ~2.5s so lazy images and font swaps don't leave the viewer stranded above or below it (stops the moment the user scrolls themselves). `.full-section`'s `scroll-margin-top: 72px` sits past the pinned header. The pinned header steps between parts in full-text mode (prev part / next part, both staying in full view); within-part section stepping is pointless there since all sections are on screen. The kicker carries a "Table of contents" link back to the section-list view. The backend endpoint reuses `store.section_html`'s per-section cache (`lru_cache(512)`), so repeat loads for one part are cheap.

**Design system — `static/styles.css`.** Modelled on Linear's dark mode, which is the default theme (light is the toggle, not the system preference). Everything is driven by the tokens at the top of the file; components never hard-code colours. Chrome (`--bg`: top bar, sidebar) is the darkest layer; `.main` and `.chat` are inset panels (`--panel`, hairline `--line` border, 12px radius, `--gutter` margin); popovers use `--pop` + `--shadow-pop`. Text is a four-step ramp `--fg` → `--fg-4` (`--fg-4` is for placeholders and separators only; it fails AA for body text). `--brand` (indigo fill) appears only on the send button and the brand mark; `--accent` is link/accent text. One sans family at weights 400/510/590, 13px for chrome, `--reader-size` (default 16px) for regulation text. Controls are 28px tall with 6px radius. Motion is short and ease-out (`--t-quick`/`--t-base`/`--t-slow`, `--ease`); route changes call `enterView()` (Web Animations fade-and-rise), and everything honours `prefers-reduced-motion`. Icons are inline 16px stroked SVGs (`icon()` / `ICON_PATHS` in `app.js`, literal SVG in `index.html`), never Unicode glyphs. Inter is first in the font stack but is not vendored, so it only renders where installed (falls back to Segoe UI Variable / system UI).

**Sidebar (`app.js`, "Sidebar: drill-down contents").** Three-tier drill-down & drill-up model: Tier 1 lists the 15 agencies (Subtitle A plus each Subtitle B chapter) as compact rows: code, short name from `AGENCY_META` (keyed by title number first, because chapter numbers repeat across titles; unlisted chapters fall back to `Ch. N` plus their own heading), and "Parts X–Y · N parts"; the "All N parts" tab instead lists every part under small agency labels. Tier 2 is one agency's parts (subchapters as labels); Tier 3 is one part's sections, grouped under foldable subpart headings (the user asked for these): each heading is a `.side-group-toggle` button with a caret, the body folds with a grid-rows transition, Alt-click folds/opens all, folded subparts persist in `localStorage` `sideFolded` as `"{title}|{part}|{subpart}"`, and the subpart holding the page on screen opens itself (in `partViewHtml` and `refreshCurrent`). Subject-group labels inside subparts stay plain. Keep it restrained: the user rejected badges, chips, per-row tags and duplicate back buttons as clutter. The sticky header is one clickable breadcrumb plus one title; the breadcrumb follows `rootViewMode` (`Agencies › OSHA › Part 1910` or `All parts › Part 1910`), and the mode switch ("By agency / All N parts" segmented pill) stays visible at every tier, lit from `rootViewMode` (the user asked to keep it; clicking an option returns to that top-level list) and hides only while the filter has text. `indexTree` stamps every `tree.json` node with a preorder key `k`, a match string `hay` (agency nodes also get their `AGENCY_META` code and name, so "osha" or "erisa" filters to the agency), a leaf count `n`, and `partCount`; `treeIdx` holds parent links, id→key maps, and agency maps. Other views call `selectTreeNode('s-<id>' | 'p-<id>')`, which switches the list to that part and resolves `agencyOf(k)`; Home, Search and not-found call `clearTreeSelection()`. Selection has two states, set both at render time (`itemHtml`, `agencyRowHtml`, `partViewHtml`) and in `refreshCurrent()`, so change them together: `.current` + `aria-current="page"` only on the page on screen (filled pill), `.ancestor-current` on the part/agency containing it (accent text, no fill). Agencies are never `.current`. The filter box (`computeFilter`) matches word prefixes across a node and its ancestors, returns agencies, parts and sections grouped under agency labels (`groupedHtml`), and is separate from the server's FTS search. Per-viewer state in `localStorage`: `visited`, `rootViewMode` ('agencies' | 'all-parts'), `sidebarW`, `sidebarHidden` (the last two are also read in the `<head>` script of `index.html` to avoid a flash; the top-left sidebar button hides the sidebar on desktop, the right edge drags to resize). The system prompt asks Claude to cite as `§ 541.100(a)(1)` because the UI linkifies that form.
