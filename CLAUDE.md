# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository layout

Two unrelated halves share this workspace:

- `reader/` — the only code: **FRAMEWORK**, a local-first Regulatory Workstation + optional Claude research assistant for multiple CFR titles (29 Labor, 40 EPA, 49 DOT are the ones the integration tests expect; any title 1–50 can be built). FastAPI + SQLite FTS5 backend, vanilla JS frontend.
- `docs/` — `docs/plans/` is organized as a **10-series** by subject (see [`docs/plans/README.md`](docs/plans/README.md) and the portfolio view [`docs/plans/MAPPED_PLAN_OVERVIEW.md`](docs/plans/MAPPED_PLAN_OVERVIEW.md)). **Implemented** in `reader/`: `12_repo_structure_stabilization/`, `21_sliding_rail_sidebar/`, `22_editorial_download_refactor/`, `23_home_screen_refactor/`, `24_dark_newsroom_multi_jurisdiction_ui/` (dark-mode-only obsidian editorial palette, 9-tier semantic reference colors & `#btn-refs-ledger`, pre-emptive multi-jurisdiction `#/corpus/` routing & Tiered Corpus Switcher, Desk filters, Authority Stack preemption strip, and Subject Workspaces housing nested Action Projects), `31_reader_development/` (unified citation parser, deterministic anchors, hover peeks, Alt-click split pane, click-to-download, broadsheet Title start with the References & Authorities hub, Cited-by/IBR graph, clause Cite/Clip) and `41_osha_news_interface/` (the `#/news` page and the inspection case file). **Not implemented**: `42_dol_api_expansion/` is the queued next plan (its MASTER_PLAN says *Do Not Execute Yet*), and `51_hse_platform_roadmap/HSE_PLATFORM_ROADMAP.md` is a strategy document (MCP server, hybrid RAG, policy linter, enterprise bots, …) that describes nothing running today. `11_multi_title_foundation/` is a historical record (Windows paths, Nov 2026 counts), not instructions. `docs/notes/2026-11-16_pre-feature-orders.md` is the cleanup dev log: Orders 1–2 (first-run profile picker, live DOL sync fixes) shipped; Order 3 (brittle JS source-slice tests, 18 mutual import cycles in the frontend, TypeScript coverage) is still open. `docs/bugs,quirks/` (the folder name contains a comma — quote it in shells) is the ingest quirks register: Titles 14 and 47 cannot be built because eCFR reuses appendix identifiers across parts and `sections.id` is the primary key (`UNIQUE constraint failed: sections.id`, QUIRK-001/002, **unresolved**; the recommended fix is a part-qualified appendix id), Title 35 is reserved (eCFR returns 404, handled), and the loose-subpart nesting is QUIRK-004. The generated GovInfo/eCFR URL inventories (`docs/dev/`, `docs/title-29/`, `docs/title-29-api/`) are gitignored and absent from this clone; the app never reads them at runtime.
- `AGENTS.md` — the short cross-tool entry point (Codex, Gemini CLI, Cursor and other agents read it). It defers to this file for detail and lists only the contracts a change must keep; when this file changes in a way that affects those contracts, update it too.

Git repo (branch `main`). No linter and no `pyproject.toml` (deliberately: setuptools trips over the multiple top-level directories); Python deps are pinned in `reader/requirements.txt` (runtime) and `reader/requirements-dev.txt` (adds pytest + exact-pinned playwright/Pillow; browser tests need a one-time `python -m playwright install chromium`). CI (`.github/workflows/ci.yml`) runs the full suite with `REQUIRE_BROWSER=1` on macOS and Windows; API payloads are pinned by golden snapshots (`tests/snapshots/`, re-record with `UPDATE_SNAPSHOTS=1`) and screenshots by per-platform Pillow baselines (`tests/baselines/{darwin,win32}/`, re-record with `UPDATE_BASELINES=1`; the `win32` set is recorded through the workflow's `record_baselines` dispatch input and downloaded as an artifact — `darwin` is current, `win32` still needs that refresh after the Milestone 1–3 UI changes). `.gitattributes` forces LF on `reader/frontend/**` because the build stamp hashes LF-normalized sources. The `origin/stage-*` branches and `stage-N-passed` tags are the merged stabilization history (PRs 1–7, Nov 16 2026), not active work. `README.md`, `reader/README.md` and `reader/API.md` describe the Regulatory Workstation for users and API clients (updated 2026-11-17); this file is the detailed description for working on the code.

`reader/data/` (SQLite DBs + tree JSON) and `.venv/` are gitignored, so a fresh clone has neither. The server starts empty on first run and shows a first-run profile picker (`GET /api/profiles`) so users can pick their regulatory domain or browse the Library instead of auto-downloading Title 29 on boot.

## Commands

The project was authored on Windows; this clone is on macOS. Python **3.10+** is required (the code uses `X | None` annotations; the macOS system `python3` is 3.9 and will fail at import — on this machine the venv is built from Homebrew `python3.12`). The venv lives at the repo root (`.venv`); commands run from `reader/` because the backend is the package `app`.

macOS / Linux:

```bash
python3.12 -m venv .venv && .venv/bin/pip install -r reader/requirements-dev.txt   # one-time, from repo root (runtime deps: reader/requirements.txt)
cd reader
../.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload   # run server
../.venv/bin/python -m app.build              # build default title (29) only if missing
../.venv/bin/python -m app.build --title 40   # build/install another CFR title
../.venv/bin/python -m app.build --force      # re-download latest eCFR edition and rebuild
../.venv/bin/python -m app.build --title 29 --renest   # fix subpart nesting of an installed title, no download
../.venv/bin/python -m pytest tests -q                       # all tests
../.venv/bin/python -m pytest tests/test_units.py -q         # one file
../.venv/bin/python -m pytest tests -q -k test_fixture_parse # one test
../.venv/bin/python -m pytest tests -q --ignore=tests/test_browser_parity.py --ignore=tests/test_milestone2_browser.py --ignore=tests/test_milestone3_browser.py   # non-browser suite, ~2 s
REQUIRE_BROWSER=1 ../.venv/bin/python -m pytest tests/test_browser_parity.py tests/test_milestone2_browser.py tests/test_milestone3_browser.py -q   # Playwright suites; fail (not skip) if Chromium is missing
UPDATE_SNAPSHOTS=1 ../.venv/bin/python -m pytest tests/test_api_snapshots.py -q      # re-record API goldens after an intended payload change
UPDATE_BASELINES=1 REQUIRE_BROWSER=1 ../.venv/bin/python -m pytest tests/test_browser_parity.py -q   # re-record this platform's screenshots
```

## Architecture (reader/)

**Multi-title federation.** Each installed title is its own SQLite DB (`data/title-{N}.sqlite3`) + tree (`data/tree-{N}.json`); `app/config.py` discovers installed titles by scanning `data/` (with legacy `title29.sqlite3`/`tree.json` fallbacks for 29). All API routes are title-scoped (`/api/{title}/…`) with unprefixed legacy aliases for Title 29; `/api/search?title=all` federates search across every installed title, merging by exact-match-then-bm25. Search results carry `title` (the title *number*) and `title_label` (the section heading) — keep both, tests and the frontend rely on this shape. Claude's tools take a `title` arg (number or `'all'`).

**Data pipeline — `app/build.py` + `app/ingest/`.** `build.py` is the orchestrator and CLI entrypoint (`python -m app.build`; `HEADERS`, `fetch_json`, `download_stream`, `log`, the SQLite schema and `build()` itself); the helpers live in `app/ingest/`: `tree.py` (`trim_tree`, `nest_loose_sections`, `normalize_scope`, `merge_scope`, `prune_tree`, `count_leaves`, `leaf_paths`, `renest` — which takes `log` as an injected parameter so it never imports build) and `parse.py` (`ecfr_path`, `front_matter_xml`, `stream_parse_xml`). `build.py` re-exports all of them, so `build.trim_tree`, `build.LEAF_TYPES`, … keep working (tests and `library/` use those names). Pulls from the eCFR Versioner API (not GovInfo), parameterized by `--title N`: `titles.json` → latest `up_to_date_as_of` edition → `structure/{edition}/title-{N}.json` + `full/{edition}/title-{N}.xml` (streamed to disk, parsed with iterparse to keep RAM flat). The **structure JSON drives ordering and hierarchy**; the full XML supplies text. eCFR's structure sometimes lists a subpart as an empty heading with its sections as siblings after it (29 CFR 1910 Subpart Z, Part 2520 Subparts D–F); `nest_loose_sections` moves them inside (plus any "Appendix … to Subpart X" after Subpart X), and `--renest` applies that to installed titles in place (tree JSON + `sections.path`). Leaves are matched by `(kind, N)` where `DIV8` = section and `DIV9` = appendix; `DIV5`/`DIV6` (part/subpart) contribute only front matter (authority, source notes) into `front_matter` keyed `part/{N}` and `part/{N}/subpart/{N}`. Each `sections` row stores both raw `xml` (for HTML rendering) and flattened `text` (for FTS and for Claude), plus `ord` (global reading order used for prev/next) and `path` (JSON breadcrumb). Writes go to a `.tmp` DB then atomically replace. Also writes `data/tree.json` (compact keys `t/id/l/d/c/r/range`) served verbatim to the sidebar. The eCFR API returns 406 unless `Accept-Encoding` is sent.

**Server — `app/main.py` + `app/routers/`.** `main.py` is only app init (GZip, `RevalidatedStaticFiles`, lifespan, `GET /`) and router mounting; the endpoints live in domain routers: `routers/deps.py` (shared `valid_installed_title`, `require_key`, `NO_STORE`, `STREAM_HEADERS`, `ChatMessage`/`ChatRequest`), `routers/settings.py` (`/api/settings/env`), `routers/library.py` (`/api/library/…`, fixed paths declared before `/{title}`), `routers/news.py` (the old `news_api.py`, plus the enforcement case-file routes), `routers/reader.py` (`/api/titles`, `/api/titles/snapshot`, `/api/profiles`, `/api/search`, the `/api/{title}` reader routes including `GET /api/{title}/references` and `GET /api/{title}/citations/{id}` served from `app/citations/graph.py`, legacy un-prefixed aliases) and `routers/chat.py` (`/api/{title}/models|chat` + legacy `/api/models`, `/api/chat`). **Mounting order is a contract** (route_inventory snapshot + precedence tests): fixed-prefix routers before the `/api/{title}` routers, legacy aliases last. Routers import whole modules (`from .. import config, library, …`), never individual functions, so test patches on module attributes stay effective. Lifespan builds nothing on an empty install (`/api/titles` returns `[]`, and legacy un-prefixed Title 29 routes return `404` via `deps.valid_installed_title(29)` while 29 is absent). `store` uses thread-local read-only SQLite connections (`timeout=5.0`, `PRAGMA busy_timeout=5000`, `PRAGMA query_only=ON`; every one also kept in a registry) and `lru_cache`s (`section_html`, `_meta_cached`, `_known_ids_cached`, …) whose helpers only cache on success (transient `(sqlite3.Error, OSError)` fails open via `safe_meta()` / `known_ids()` without caching empty fallbacks). `store.begin_swap(n)` / `end_swap(n)` coordinate with `library.jobs.run_job` around installs, and `store.release_title(n)` closes every thread's connection to a title, bumps its generation (each thread reopens on its next query) and clears the caches (including the citation graph index via `graph.clear_caches()`); the library calls it before replacing or deleting a title's files, because Windows refuses while any handle is open. A CLI rebuild (`python -m app.build`) still needs a **server restart** to be seen.

**Profiles / first run — `app/profiles.py`, `GET /api/profiles`, `views/welcome.js`.** `PROFILES` is pure data (`id`, `name`, `description`, `downloads` of `{title}` or `{title, part}` strings); `TITLE_NAMES` covers all 50 titles so the picker renders offline before any eCFR request. When `/api/titles` returns `[]`, `init` sets `state.noTitles = true`, disables search/chat (`setReaderEnabled(false)`), and `router.js` renders `renderWelcome()` for `/` and reader routes while keeping cross-title verticals (`/library`, `/news`, `/projects`, `/settings`, `/help`) reachable. Picking a profile queues downloads via `POST /api/library/download` (`installProfile`), `pollJobs` keeps the inline progress slot current via `refreshWelcome()`, and `refreshTitles()` wakes the reader and opens the first landed title's start page.

**Library — `app/library/`, `#/library…`.** A package: `client.py` (eCFR client + catalog caches `_catalog`/`_structures`), `suites.py` (`COMPLIANCE_SUITES`, `DESKS`, `_BLURBS`), `disk.py` (`installed`, `storage`, `prune_temp`, `remove`, `_remove_partial_files`), `views.py` (`title_view`, `part_view`, `changes`, `wire`), `jobs.py` (`Queue`, `run_job`, `queue_titles`, `update_all`, and the `queue = Queue()` instance) — deliberately **not** named `queue.py`/`storage.py`, which would shadow the re-exported `queue`/`storage()`. `library/__init__.py` re-exports the whole old surface, and submodules call every patchable function through the package (`lib.run_job`, `lib.queue`, `lib.ecfr_titles`, …) so test patches on `app.library` attributes stay effective. Download a whole title, a part or single sections/appendices (not paragraphs) from eCFR. A partial install stores its scope in `meta.scope` (`{"parts": [...], "sections": [{"t","id","part"}]}`; absent = whole title; `build.normalize_scope` drops sections inside selected parts). `build.build(scope=…)` prunes the structure (`prune_tree`, keeps ancestors) and fetches one XML per part (`?part=`), section (`?section=`) or appendix (`?part=&appendix=`, since appendix ids repeat across parts). Downloading more of a title rebuilds it with `merge_scope(old, new)` at the latest edition; the whole title replaces a partial copy; a same-scope same-edition request is a no-op ("Already installed"). Jobs run one at a time on a daemon thread (`library.queue`), reporting `phase/done/total` via `build(progress=…)`. Endpoints: `GET /api/library` (all 50 titles + install state + jobs + `desks`; each title row also carries `summary`, `desk`, `featured` from `app/title_blurbs.json` and `amended` = eCFR's `latest_amended_on`; a title with no entry in the JSON gets an empty summary and the "More titles" desk), `GET /api/library/{t}` (parts by chapter), `GET /api/library/{t}/part/{p}` (sections by subpart), `POST /api/library/download` `{title, part?, section?, kind}`, `POST /api/library/{t}/update`, `DELETE /api/library/{t}` (refused for the last installed title or one with a job), `GET /api/library/jobs`. eCFR's title list is cached 30 min, structures per (title, edition). Frontend: `loadLibrary`/`renderLibrary` (three levels like the sidebar, filter box, row actions that swap with the status column on hover, Remove is two clicks). The top level (`libFrontHtml`) is a newsroom front page, built from `docs/plans/20_app_shell_and_workspace/22_editorial_download_refactor/`: masthead (edition, active titles, amended this week) → four metric tiles (`libMetrics`: eCFR checked-at, installed count/sections/disk, amended in the 7 days before the newest edition, outdated editions with **Update all**) → the broadsheet lead, the featured compliance suite (`suiteHero`, 65%: its titles with agencies, top parts from `HOME_CONTENT`, per-title dateline and status, one batch button) beside **The Regulatory Wire** (`libWire`, 35%: the five most recently amended titles; what changed fills in from `GET /api/library/wire`, cached client-side 30 min) → the other suites (`suiteCard`) → filter + order control (desk / number / recently amended, `localStorage` `libSort`) → every title as a brief (`libStory`) under its topic desk, desk headers counting titles ("2 of 6 titles" while filtering). A brief: kicker ("Title 29 · OSHA WHD EBSA"), status pill top right, headline (the whole card links to `#/library/{t}`), summary, dateline (amended · sections · size); actions (`titleActions`) slide in over the dateline on hover/focus, painted in the card's colour (`--story-bg`). The filter matches number, name, summary, desk and agency acronyms. Widths follow the page via container queries (`.lib-front` is `container: lib`): 3 brief columns ≥1000px, metrics 2×2 and the broadsheet stacked ≤760px, 1 column ≤560px. Status is a 6px dot + word everywhere (`statPill(state, text)`; states synced / stale / busy / partial / uninstalled; `is-bare` drops the outline in dense rows); `titleStatus(t)` decides a title's. The summaries are scope-only editorial copy (≤140 chars, enforced by `tests/test_library_front_page.py`); `title_blurbs.json` also holds each title's main `agencies` (acronyms) and the measured `size_mb`/`sections` estimates (from eCFR's structure JSON, 2026-11-12 edition). eCFR's `search/v1/counts/titles` is not a section count (it disagrees with installed counts), so it isn't used. Suites are `library.COMPLIANCE_SUITES` (ehs 29/40/49 featured, trade 12/15/17, govcon 41/48); a new one is one dict entry. Batch endpoints: `POST /api/library/batch-download` `{suite}|{titles}` (`library.queue_titles`: skips reserved and current titles, updates stale whole ones, completes partial ones), `POST /api/library/update-all` (`library.update_all`, keeps each title's scope), `POST /api/library/jobs/{id}/cancel`, `POST /api/library/jobs/clear`. Cancelling a running job sets `cancelling`; the job's progress callback raises `JobCancelled` at its next report (never once it reports `Installing`, when files are being swapped) and `_remove_partial_files` deletes its `.tmp` files. While a whole title's XML streams, `build` reports bytes against Content-Length or, without one, decoded bytes against the structure's `size`, so the dock can show real progress, speed and ETA. **Transfer dock** (`#transfer-dock` in `index.html`, "Transfer dock" in `app.js`): a floating card at the bottom right of the reading panel (moves left of the chat when it's open; hidden under 900px while the chat covers the page), mounted outside `#view` so routing never touches it; `setJobs` → `updateDock()`. It shows the running job, its pipeline step (`DOCK_STEPS`, six ticks), a 3px progress bar (indeterminate when unmeasured), MB of MB · speed (EMA over polls) · time left, and what's queued, with Cancel and Clear queue; it minimizes to a pill (`localStorage` `dockMinimized`). It rebuilds its markup only when its shape changes (job, step, queue) and patches numbers in place otherwise, so the bar animates and focus stays put; screen readers get one polite line per step (`#transfer-dock-live`). `pollJobs` (runs while jobs are active, wherever the reader is; on completion toasts — done, error or cancelled — `refreshTitles()` refills the title switcher and reloads the current title if it changed; the library re-renders only when the set of active jobs changes), entered from Home's **Manage library** / **Add or update titles** links or the Library rail button. `/api/titles` carries `partial`. If Title 29 is not installed, the frontend starts on the first installed title.

**Citations — `app/citations/` (Plan 31 Milestone 1).** `parser.py` is the single grammar for CFR, U.S.C., FR and web references: the token pieces (`SEC_NUM`, `SEC_TOKEN`, `PARA_OPT`, `LIST_SEP`, `PART_NUM`), the legacy patterns whose group layout `news.extract_citations` depends on (`XREF_RE`, `WORD_SEC_RE`, `NUM_IN_LIST_RE`, `CROSS_TITLE_RE`), the extended reader patterns that stop a list item from swallowing a following `N CFR` / `U.S.C.` citation (`XREF_EXT_RE`, `WORD_SEC_EXT_RE`, `CROSS_TITLE_EXT_RE`, `CROSS_TITLE_PARTS_RE` — the fix for "40 CFR parts 264 and 265" once linking to Title 29 Part 264), `USC_RE` (multi-letter sections, lists, ranges), `FR_RE`, `WEB_URL_RE` with `clean_url_tail` (strips trailing sentence punctuation from URLs), paragraph tuples (`PARA_OF_SEC_RE`, `PARA_SELF_RE`, `expand_paragraph_list`) and `extract_reference_spans(text, current_title)` → typed `CitationSpan`s. `render/linkifier.py` and `news.py` import their regexes from here; `frontend/src/citations.ts` (`NEWS_CITE_RE`) is kept in parity by `test_news_frontend.py`. `graph.py` builds one `lru_cache`d index per title (`_build_title_index`: a single pass over every `sections.text` row) holding the web-reference directory (hosts classified standards / portals / agencies / technical from `_STANDARDS_HOSTS` / `_PORTAL_HOSTS`, retired hosts flagged with a replacement from `_LEGACY_HOSTS` such as wdol.gov → SAM.gov, every URL with the sections that cite it), reverse backlinks (which sections cite each section) and the title's IBR catalog (consensus standards like `ANSI Z89.1-2009` parsed by `STANDARD_CODE_RE` over `SDO_ORGS` from incorporation-by-reference sections such as § 1910.6 — `_is_ibr_catalog_section`). `get_references(title)` serves `GET /api/{title}/references` (`items`, `hosts`, `ibr_standards`, `most_cited` and their counts); `get_section_graph(title, id)` serves `GET /api/{title}/citations/{id}` (`cited_by`, `cited_by_count`, `ibr` matches with `approved_in` and an `exact` flag for full-code vs base-code hits; 404 for an unknown section). `graph.clear_caches()` is called from `store.clear_caches()` and `store.release_title()`, so installing or removing a title invalidates the index. `tests/test_graph.py` augments the fake Title 29 with a § 1910.6 IBR row to exercise both endpoints.

**Rendering — `app/render/`.** A package (`text.py` plain-text flattening, `hierarchy.py` `LevelTracker`/`compute_levels`, `linkifier.py` citation regexes + `make_linkifier`, `units.py` `SectionDoc`/`split_units`, `html.py` `Renderer`/`image_urls`/`render_leaf_html`/`render_fragment_html`); `render/__init__.py` re-exports everything, so `from .render import …` is unchanged (`news.py` imports `_CROSS_TITLE`/`_XREF`/`_NUM_IN_LIST` from it). `units.py` defers its `Renderer` import inside methods because `html.py` imports `units` at the top. HTML is rendered from stored XML on request (cached), not at build time. `LevelTracker` infers indentation depth from paragraph markers `(a)→(1)→(i)→(A)`. A lone `(i)`/`(v)`/`(x)` is both a letter (level 1) and a roman numeral (level 3); it is resolved from the next paragraph's marker (`(ii)` → roman, `(j)` or `(1)` → letter) and from what came before (last clause letter, last roman). `compute_levels(root)` runs the tracker once over the whole section, keyed by `id(element)`, so rendering any slice indents exactly as the full text does; `Renderer` only looks levels up. `make_linkifier` turns `§`/`§§` citations (lists, ranges, paragraph suffixes) into links, but only for IDs present in `known_ids()`. HTML output is escaped/whitelisted (e.g. `SAFE_CELL_CLASSES`). Figures: eCFR's `/graphics/erDDmmmYY.NNN.gif` paths are dead; `image_urls` maps them to `img.federalregister.gov/{ID}/{ID}_large.png` (what eCFR itself uses), wrapped in a `.reg-figure` link to `_original_size.png`. ~45 legacy names (`53-49a.eps.gif`) have no known URL; the reader swaps a failed figure for a "view on eCFR" link. **Deterministic anchors**: `Renderer._unique_anchor` de-duplicates ids within one render; paragraphs get `p{n}`, tables `table-{slug}` from their caption (`_TABLE_ID_RE`), embedded appendices `<section class="reg-appendix" id="appendix-{x}">`, footnotes `fn-{slug}` with `<button class="ftref" data-anchor=…>` references and jump-back links (`_try_ftref_pair`, `_fn_dom_id`); `views/doc_utils.enhanceDomAnchors` adds figure ids (`fig-{slug}`) client-side and turns in-text "Table Z-1" / "Figure 1" / "Appendix A" mentions into `button.xref-anchor[data-anchor]` peek triggers. **Link classes**: `make_linkifier(known, title, known_by_title, installed_titles, known_parts, section_id)` emits `a.xref` (a section of this title), `a.xref-local[data-local-para]` (a paragraph of the section being rendered), `a.xref-cross` (a section of another installed title), `a.xref-external[data-cfr-title|part|section|para]` (an uninstalled title — the href is eCFR, but `peek.js` intercepts the click for the download card), `a.xref-usc`, `a.xref-fr` and `a.xref-web`; the frontend's peeks, split pane and resolver key off these classes, so changing them means changing `peek.js` / `doc_utils.js` too. `ingest/tree.py`'s `trim_tree` runs `render.text.clean_label` over eCFR labels so the HTML tags eCFR ships inside `label_description` never reach `tree.json` or `sections`.

**Units — `SectionDoc` / `split_units` in `render/units.py`.** Every section is cut into reading units: each top-level lettered clause `(a)`, `(b)`, … (text before `(a)` joins it), and each appendix embedded in the section as an `<EXTRACT>` headed "Appendix X to §…" (58 Title 29 sections do this, e.g. § 1910.1200, § 1910.1027, § 1910.134). An embedded appendix over `APPENDIX_SPLIT_MIN_CHARS` splits again at its own HD1 headings (A.0, A.1 …; HD2 as fallback; Figure/Table captions skipped); a long standalone text with no clauses splits the same way. A section is `mode: "units"` (read a unit at a time) when it has an embedded appendix or more than `UNIT_MODE_MIN_CHARS` of text; otherwise `"page"`. `full_html()` wraps each unit in `<section class="reg-unit" id="u-{key}">` and renders embedded appendices plainly (no extract callout). Unit keys: clause letter (`c`), `appendix-a`, `appendix-a-a-1` (chapter A.1); a group key opens its first chapter. `store._section_doc` caches the parsed doc; `section_html` / `unit_html` cache renders. `GET /api/{title}/section/{id}` returns `mode`, `outline` (every unit: key, label, title, kind, group, group_label, group_title, chars) and, with `?unit=KEY` (`?unit=` = first) on a units-mode section, only that unit's `html` plus `unit`, `unit_prev`, `unit_next`; without `unit` it returns the whole section as before.

**IDs.** `store.normalize_id` accepts `§ 541.100`, `29 CFR 541.100`, `541.100(a)(1)` → `541.100`. All endpoints and Claude tools go through it.

**Search — `store.search`.** Exact section-number hit is prepended, then FTS5 (`porter unicode61`) ranked by `bm25` weighted toward label/title. `fts_query` quotes every token (so user input can't inject FTS syntax) and adds a prefix `*` to a final bare token of ≥5 chars. Everything is driven by `:root` tokens at the top of `01_tokens.css`; the app is locked to obsidian dark mode (`color-scheme: dark`, `@media print` still renders black-on-white paper output). Surfaces follow the obsidian ink ramp `--bg` (`#070708`) → `--panel` (`#0B0B0D`) → `--card` (`#111114`) → `--pop` (`#151519`), inset chrome (`12px` radius, hairline `--line` border), text opacity ramp (`--fg` / `--fg-2` / `--fg-3` / `--fg-4`), surgical editorial stamps (`--editorial-crimson: #E11D48`, `--editorial-gold: #EAB308`), and **9-tier semantic reference colors** (`--ref-local`, `--ref-cfr`, `--ref-cross`, `--ref-uninstalled`, `--ref-usc`, `--ref-fr`, `--ref-ibr`, `--ref-state`, `--ref-county`) driving inline `.xref*` links, `.citation-chip[data-ref-tier]`, `.has-tier-bar` 3px left bars, `#cite-pop[data-ref-tier]` 2px colored top borders, and `.split-head[data-ref-tier]`. `--fig-mat` uses warm dark-room slate (`#D4D4D8`) for Federal Register diagrams. Status (`statPill`) remains strictly reserved for sync/download state. Layout breakpoints inside panes use `@container` queries (`.main` → `main`, `.split-pane` → `split`, `.ts-front` → `title-start`, `.hm` → `hm`, `.lib-front` → `lib`, `.news-front` → `news`, `.settings-front` → `settings`, `.help-front` → `help`).

**Navigation — activity rail + sliding drawer (`app.js` "Navigation", built from `docs/plans/20_app_shell_and_workspace/21_sliding_rail_sidebar/`).** The layout is four fixed grid tracks, `var(--rail-w) var(--drawer-col) minmax(0,1fr) var(--chat-col)`, so the drawer and the chat animate their widths instead of jumping. The **rail** (`#activity-rail`, 48px, chrome `--bg`) holds the landmarks in order Home · Title start · Contents · Workspaces · News · Library · Settings (bottom): Home, Title start and News are links (`aria-current`), the others are buttons (`aria-expanded`, `aria-controls="sidebar"`) that open a panel in the **drawer** (`#sidebar`), toggling it closed when re-clicked. Exactly one item is lit (`.is-active`: pressed fill + 3px accent bar): the open panel's, else the page's landmark (`routeTarget`). Labels with their shortcut show on hover (CSS `::after` from `data-tip`/`data-keys`); the Library icon carries a badge (`#ar-library-badge`: pulsing while downloading, amber when installed titles are outdated). Under 900px the rail is a bottom bar (`--bar-h`). The drawer has a 40px header (title, meta, panel actions, pin/overlay toggle, close) and **persistent panels** (`.drawer-panel[data-panel]`: reader = the contents tree below, projects, library, settings, history), shown one at a time and never re-mounted, so the tree keeps its place; `.drawer-inner` keeps the drawer's width while its track animates. State (`localStorage` `railState` `{panel, collapsed, mode, width}`, also read by the `<head>` script to avoid a flash; the old `sidebarW`/`sidebarHidden` keys are read once as fallbacks): `html.drawer-collapsed` (put away), `html.drawer-retracted` (Home and a title's Title start put a pinned drawer away for the page's width, not persisted), `html.drawer-fly` (the drawer floats over the page, frosted, with a backdrop: overlay mode, any width ≤900px, or ≤1200px while the chat is open; `body.nav-open` = out; it closes on navigation, Esc or a backdrop click). `syncNavToRoute` runs on every route: entering `#/library…` shows the Library panel, `#/projects…` Workspaces, and a reader page swaps Library/Recent for Contents. Re-clicking Home or Title start while on it opens **Recent** (reading history from `usage`, grouped Today/Yesterday/This week/Earlier, plus the latest pins). **Library panel**: a "Browse the library" card, Transfers (only while active; the floating dock steps aside via `body.drawer-library`), installed titles with status dots and "Update N", suites with a batch download button (`/api/library`, cached 60s in `navLib`). **Settings panel** (deliberately light): quick settings (theme, reading text A−/A+ stepper sharing `fontSize` via `applyFontSize`, drawer mode), quick actions (Edit API keys → the `.env` modal, Check for news, Connections & API keys → `#/help`), and one **Open settings** CTA to the full page. **`#/settings` page** (`renderSettingsPage`, cross-title like `#/projects`; `routeTarget` maps `/settings` and `/help` to the Settings landmark, which retracts a pinned drawer): cards for Appearance, Claude model (mirrors `#model-select`), News status, storage (`GET /api/library/storage`: bytes per title, Title 29's legacy copy, leftover `.tmp` files; `POST /api/library/storage/prune` deletes those, refused with 409 while a download is active), and the keyboard cheatsheet. Panel and page share builders (`settingSeg`, `settingsClaudeHtml`, `settingsStorageHtml`, `settingsKeysHtml`, `newsSettingsHtml`) and the `[data-set]`/`[data-set-act]` handlers (`runSettingsAction`, delegated on both `#sidebar` and `#view`); `refreshSettingsViews()` re-renders whichever is on screen. The rail's Settings icon is a gear (24-grid Feather path with inline `stroke-width="2.25"` to match the 1.5px icon stroke), not the old circle-and-rays glyph that read as a theme toggle. Keys: ⌘B/Ctrl+B toggles the drawer; **G then H/T/C/P/N/L/S** goes to a rail item (`G O` stays an alias for `G H` Home; Linear-style; ⌘1–5 would be eaten by the browser's tab switching), Alt/⌥+1…7 too; ⌘D pins; Esc closes a floating drawer; `>` in the search box lists commands (`commandList`: go to, panels, new workspace, theme, drawer, chat, each workspace, other titles). Keyboard openings focus the panel's first control (the tree filter for Contents); closing returns focus to the rail; a hidden drawer is `inert`. The rail arrows (↑↓, ←→ as a bottom bar, Home/End) move between items.

**Projects (`views/projects.js`, labeled "Workspaces" in the UI).** Workspaces of pinned sections, per browser in `localStorage` `framework_projects_v1`: `{id, name, description, tags[], created_at, updated_at, sections[{title, id, label, heading, part, pinned_at, note}]}`. A clause **Clip** (`clipToWorkspace(sec, {para, quote, cite, projectId})`) pins the section if needed (into the first workspace, creating "Research clips" when there is none) and appends a `[cite] "quote"` line to that section's `note` — clips are not a separate field. Pin the open section with the **Pin** button in the section's actions row or ⌘D: a popover lists workspaces as checkable rows and creates a new one from its input. `#/projects` lists workspaces as briefs (kicker with the workspace's colour dot from `PROJECT_HUES` tokens, name, description, tags, "N sections · Titles …"); `#/projects/{id}` edits in place (name as the headline input, description, tags, a note per pinned section; saved 300ms after typing with `saveProjects(…, {quiet: true})` so the page isn't re-rendered under the cursor), with Export (JSON) and two-click Delete/Remove. Sections of titles that aren't installed say so and link to the library. The drawer's Workspaces panel lists workspaces (current one lit), creates them inline, and exports/imports all of them via "Import file" (`{format: 'framework-projects', version: 1, projects}`; an import keeps the newer copy of a workspace by `updated_at`).

**Sidebar (`app.js`, "Sidebar: drill-down contents"; the drawer's Contents panel).** Three-tier drill-down & drill-up model: Tier 1 lists the 15 agencies (Subtitle A plus each Subtitle B chapter) as compact rows: code, short name from `AGENCY_META` (keyed by title number first, because chapter numbers repeat across titles; unlisted chapters fall back to `Ch. N` plus their own heading), and "Parts X–Y · N parts"; the "All N parts" tab instead lists every part under small agency labels. Tier 2 is one agency's parts (subchapters as labels); Tier 3 is one part's sections, grouped under foldable subpart headings (the user asked for these): each heading is a `.side-group-toggle` button with a caret, the body folds with a grid-rows transition, Alt-click folds/opens all, folded subparts persist in `localStorage` `sideFolded` as `"{title}|{part}|{subpart}"`, and the subpart holding the page on screen opens itself (in `partViewHtml` and `refreshCurrent`). Subject-group labels inside subparts stay plain. Keep it restrained: the user rejected badges, chips, per-row tags and duplicate back buttons as clutter. The sticky header is one clickable breadcrumb plus one title; the breadcrumb follows `rootViewMode` (`Agencies › OSHA › Part 1910` or `All parts › Part 1910`), and the mode switch ("By agency / All N parts" segmented pill) stays visible at every tier, lit from `rootViewMode` (the user asked to keep it; clicking an option returns to that top-level list) and hides only while the filter has text. `indexTree` stamps every `tree.json` node with a preorder key `k`, a match string `hay` (agency nodes also get their `AGENCY_META` code and name, so "osha" or "erisa" filters to the agency), a leaf count `n`, and `partCount`; `treeIdx` holds parent links, id→key maps, and agency maps. Other views call `selectTreeNode('s-<id>' | 'p-<id>')`, which switches the list to that part and resolves `agencyOf(k)`; Home, Search and not-found call `clearTreeSelection()`. Selection has two states, set both at render time (`itemHtml`, `agencyRowHtml`, `partViewHtml`) and in `refreshCurrent()`, so change them together: `.current` + `aria-current="page"` only on the page on screen (filled pill), `.ancestor-current` on the part/agency containing it (accent text, no fill). Agencies are never `.current`. The filter box (`computeFilter`) matches word prefixes across a node and its ancestors, returns agencies, parts and sections grouped under agency labels (`groupedHtml`), and is separate from the server's FTS search. Per-viewer state in `localStorage`: `visited`, `rootViewMode` ('agencies' | 'all-parts'); the drawer's width and visibility are the navigation's (below). The system prompt asks Claude to cite as `§ 541.100(a)(1)` because the UI linkifies that form.
